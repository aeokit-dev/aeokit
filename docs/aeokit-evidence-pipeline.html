The big picture

aeokit becomes an evidence machine.

It watches AI answers and business activity, turns messy signals into clean facts, then finds the next best opportunity automatically.

In plain English The system collects proof first. Rules decide what the proof means. An LLM only explains the result or drafts the next action.

The mental model

Three jobs. Clear boundaries.

Keeping these responsibilities separate makes the system easier to trust and easier to debug.

01

Machines collect the proof

Schedulers, providers, crawlers and analytics continuously produce observations.

02

Rules make the decision

A known condition maps to a known opportunity. The same evidence gets the same result.

03

The LLM explains it

It summarizes the evidence and drafts an action, but it does not invent the trigger.

Reliable execution

Every run has a visible, recoverable journey.

Users see progress immediately. Temporary provider problems do not destroy the evidence trail.

QueuedStart once

An idempotency key blocks accidental duplicate runs.

RunningCall provider

Run Now is disabled while work is active.

WaitingBack off

Polling slows progressively and respects provider timeouts.

RetryingPreserve failure

The original error remains available as evidence.

FallbackTry alternate

Optionally switch from Bright Data to DataForSEO.

CompleteStore both

Keep the fallback result beside the first attempt.

unique run = project_id + prompt_id + provider + scheduled_window
